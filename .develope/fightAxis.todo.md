# 要做什么

## 一. 排轴JSON文件内容格式协议规范

### 1. 需要完成的工作

- 新增针对 fight_axis 的 schema 协议

- 将原有默认战斗技能流程写入 default.json 以默认使用

- 完成对 json 文件排轴信息的读取

- 面向用户的排轴文件导入功能

### 2. 文件内容

#### (1) 定义对象类型

I.  技能类型  
    分三类: 一般战技, 连携技, 终结技

II. 内部对象子成分
    含两个: 技能类型 (参考 I), 角色对象 id (限制为 1~4 的正整数)

#### (2) 定义内容板块

分两类: 检测到满足释放条件时立刻释放类 (仅限终结技和连携技), 依次释放类 (三种技能均可, 但具体技能不可与立即释放类内技能有交集)

## 二. 改 go-agent 战斗技能释放逻辑

### 1. 现有工作模式分析

现有的 go-agent 自动战斗工作流程是 "检测可以释放的技能类型, 并直接添加到动作序列".

注意到如果反过来操作, 每次使轴队列最前一个操作出队, 并检查是否符合释放条件, 即可实现排轴效果.

### 2. 需要添加的工作流程

- 读取当前激活的 json 排轴文件信息

- 改写 go-agent 技能释放检测逻辑

- 对轴队列添加舍弃功能防止卡死

- (可选) 添加补偿机制, 防止技能后续暖好了没放浪费

## 四. 可复用按钮控件与接口适配草案

### 1. 目标

将“复制自定义轴”“导入自定义轴”这类一次性动作从普通选项中拆出来，做成可复用的按钮控件，供协议空间、排轴管理，以及未来其他工具类任务复用。

### 2. 核心设计原则

- 按钮只负责“触发动作”，不承载业务状态。
- 按钮应能复用同一套执行后端，不为每个任务重复写一套 custom action。
- 按钮必须支持确认、失败提示、成功提示、禁用态和作用域限制。
- 按钮控件不应破坏现有 `select` / `switch` / `checkbox` / `input` 的兼容性。

### 3. 建议的接口模型

建议在 `interface.json` 的 `option` 中增加一种新类型：`button`。

推荐字段如下：

- `type: "button"`：标识为按钮控件。
- `label`：按钮显示文本，支持国际化。
- `description`：按钮用途说明，支持国际化。
- `icon`：可选图标。
- `controller` / `resource`：可选适用范围，用于控制按钮是否显示。
- `action`：点击后触发的动作标识，映射到 Go Service 或客户端命令。
- `confirm`：是否需要确认弹窗，或确认文案。
- `success_message`：执行成功后的提示文案。
- `failure_message`：执行失败后的提示文案。
- `pipeline_override`：可选，用于按钮点击前后做状态切换、启用禁用或参数传递。

### 4. 推荐的按钮语义

考虑到 "激活" 开关已经有合适的控件承担该功能, 目前仅考虑增加 "立即执行" 类按钮控件, 配合 agent 等其他项目组成部分完成复杂操控工作

点击后直接执行动作，例如：

- 复制文件到剪切板
- 打开文件选择器并导入文件
- 刷新某个缓存

这类按钮不改变任务主流程，不应依赖任务运行状态。

### 5. 与现有任务配置的适配方式

建议保留现有 `task.option` 的 `select` / `switch` 语义不变，同时增加一类 `button_group` 或 `buttons` 概念，用于仅展示按钮，不参与预设值序列化。

如果不想增加新的顶层配置块，也可以允许 `option.type = "button"`，但在任务配置保存时：

- 不写入 `caseName`
- 不参与 `default_case`
- 不进入任务预设快照
- 只保存按钮点击事件的参数

### 6. 执行链路建议

推荐按钮触发链路如下：

1. GUI 渲染按钮。
2. 用户点击按钮。
3. 客户端把 `action` 与参数发给 Agent。
4. Agent 调用对应 Go Service custom action。
5. Go Service 处理文件读写、剪切板、文件选择、提示弹窗。
6. 处理结果回传 GUI，显示成功或失败消息。

### 7. 这次排轴需求的落点

如果按按钮控件落地，这两个按钮可以这样定义：

- `copy_custom_axis`：读取 `assets/fight_axis/user_axis.json`，复制到系统剪切板，提示“已复制自定义排轴文件内容”。
- `import_custom_axis`：打开文件选择器，选择 JSON 文件后完整覆盖 `assets/fight_axis/user_axis.json`。

下拉框则保留为：

- `default_axis`：激活 `assets/fight_axis/default.json`
- `custom_axis`：激活 `assets/fight_axis/user_axis.json`

### 8. 复用建议

建议把按钮相关能力拆成三层复用模块：

- `button registry`：注册按钮 action 名称与处理函数。
- `file operations`：文件读写、覆盖、备份、校验。
- `ui bridge`：消息弹窗、确认弹窗、文件选择器、剪切板。

这样后续别的任务如果也需要“导入”“复制”“重置”一类动作，可以直接复用，不必每个任务都新增一套接口。

### 9. 需要确认的实现前提

- GUI 端是否已经有新增 option type 的渲染入口。
- 任务预设是否允许按钮型项完全不参与存档。
- Agent 与 GUI 的事件通道是否支持一次性命令型操作。
